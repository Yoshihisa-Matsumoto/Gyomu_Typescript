# Gyomu Config

[US English](README.md) | JP 日本語

## 概要

本パッケージは、Gyomuプロジェクトにおける集中型の設定管理システムです。グローバルおよびユーザーごとのスコープにわたる設定の取得、検証、階層的なマージを調整し、アプリケーションの整合性のある動作を保証します。

Effect Schemaによる厳格な検証を統合することで、プラットフォームは未加工の設定データを型安全で実行環境を考慮した結果へと変換します。このアプローチにより型安全性と信頼性が確保され、アプリケーションエコシステム全体で一貫した設定基準を強制する堅牢な基盤を提供します。

## アーキテクチャ

@gyomu/configパッケージは、設定の解決ライフサイクルを統合管理するシステムとして構成されています。コアとなる解決サービスを使用し、グローバル、ユーザー、スコープベースのソースから設定を取得、検証、マージして、一貫性のある型安全な構造にまとめます。このサービスは主要なエントリポイントとして機能し、階層的な優先順位ルールとスキーマ検証を適用することで、アプリケーションに値を提供する前にデータ整合性を保証します。

このプロセスをサポートするため、本パッケージには障害を捕捉、分類、報告する専用のエラー処理レイヤーが含まれています。このコンポーネントは解決のフェーズを追跡し、エラーに診断メタデータを付加することで、システムが障害の発生段階を特定し、潜在的な復旧アクションを判断できるようにします。コアの解決ロジックと診断報告を分離することで、アプリケーションのライフサイクル全体を通じて設定状態を確実に管理し、障害を透過的に処理できるアーキテクチャを実現しています。

## インストール

pnpmを使用してインストールしてください。

```bash
pnpm add @gyomu/config
```

## 依存関係

本パッケージはNode.jsを必要とし、ESM環境専用に設計されています。Effect 4.xと互換性があり、そのランタイム、スキーマ、およびコンテキスト機能を中核基盤として活用しています。

機能は、共有型およびスキーマ定義のための`@gyomu/schema`、およびベースラインとなるI/O操作のための`@gyomu/infra`との統合によって拡張されます。ライブラリのインフラストラクチャをサポートするため、これらのピア依存関係がプロジェクト内で適切に設定されていることを確認してください。

## 開発

本パッケージの開発哲学は「構築による正しさ」の原則に根ざしており、設定を単なるキーと値のペアの集まりではなく、正式なデータコントラクトとして扱います。Effect Schemaを活用することで、可能な限り早い段階で厳格な型安全性と実行時検証を強制し、無効な設定がアプリケーションのビジネスロジックに伝播する前に排除します。このアプローチにより、設定は実行時バグの一般的な原因から、階層的な継承の複雑さに関わらず環境の完全性を保証する予測可能でイミュータブルなインフラストラクチャ層へと変貌します。

このプラットフォームは、異種ソースをマージする「方法」である解決戦略と、アプリケーション統合の「何」であるコンシューマー向けAPIを明確に分離して設計されています。コントリビューターは、コアロジックを変更することなく新しい設定ソースや解決ルールを追加できるよう、拡張性とモジュール性を優先してください。関数型プログラミングにおける純粋性の維持は不可欠であり、状態管理とエラー処理は予測可能である必要があります。また、あらゆる解決失敗に対して、追跡可能な豊富なメタデータを提供しなければなりません。この厳格な分離と内部の一貫性を維持することで、Gyomuがグローバルなユーザースコープ全体でスケールしても、システムが回復力、保守性、および厳密な型付けを維持できるようにしています。

## Public API

- 設定解決 - グローバル、ユーザー、スコープ定義に優先順位ルールを適用し、多層的な設定取得を調整します。
- 型安全な設定アクセス - 検証済みかつ型安全な設定データをアプリケーションコンポーネントに提供するサービスインターフェースを公開します。
- 解決診断 - 開発者が設定参照プロセス中の障害箇所をトラブルシューティングおよび特定できるよう、構造化されたエラーコンテキストを提供します。
